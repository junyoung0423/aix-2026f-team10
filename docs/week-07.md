## 1. 아키텍처 다이어그램 / Architecture Diagram
 
손그림 사진을 올리고 링크하십시오 / Upload a photo and link it.
 
<img width="1288" height="951" alt="image" src="https://github.com/user-attachments/assets/80a245f9-d6e3-45e7-8d69-9a575b60ea8b" />

> 우리 프로그램은 식당처럼 세 층으로 나뉩니다.
> **표현**은 손님을 맞는 홀(화면), **로직**은 요리하는 주방(계산·판단), **데이터**는 재료 창고와 납품업체(저장·외부 도구)입니다.
> 주방은 "이런 재료가 필요하다"는 주문서(포트)만 쓰고, 어느 업체 재료인지는 신경 쓰지 않습니다. 그래서 도구를 바꿔도 주방 코드는 그대로입니다.
 
| 계층 / Layer | 모듈·파일 / Modules | 의존하지 않는 것 / Does not depend on |
|---|---|---|
| 표현 / Presentation | 피팅 화면(치수 입력·결과 보기), 옷 등록 화면, 템플릿 만드는 명령어 도구 | 계산이나 판단을 하지 않습니다. 저장소나 Blender·AI 같은 외부 도구를 직접 부르지 않고, 로직 계층에만 요청합니다 |
| 로직 / Logic | 서비스(작업 순서를 정하는 역할): 피팅, 옷 등록, 템플릿 만들기 / 실제 계산: 핏 분석기, 몸 최적화, 패턴 검색, 패턴 최적화, 실사화·검증, 영상·검증 / 포트(필요한 기능 목록) | 화면이 어떻게 생겼는지, 어떤 외부 도구를 쓰는지 모릅니다. Blender·AI·DB는 포트를 통해서만 사용합니다 |
| 데이터 / Data | 저장소: 옷, 결과, 패턴 견본(패턴 라이브러리), 모델 에셋(3D 몸·전속 모델 사진 등) / AI Hub 옷 데이터 가져오기 / 외부 도구 연결: GarmentCode(옷 도면→3D), SMPL(3D 몸), Blender(입히기·촬영), Nano Banana(사진처럼 바꾸기), 분할 모델(옷 영역 찾기), 영상 API | 화면을 모르고, 작업 순서도 정하지 않습니다. 로직이 정한 포트대로 기능만 제공합니다 |
 
## 2. 이슈 / Issues
 
> 이슈 = **앞으로 할 일** / An issue is work to be done.
> 개발할 때 커밋에 이슈 번호를 붙이고(`#3 알레르기 필터 추가`), 완료 조건을 만족하면 이슈를 닫습니다.
> Add the issue number to commits, and close the issue when its criteria are met.
