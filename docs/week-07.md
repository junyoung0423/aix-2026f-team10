## 1. 아키텍처 다이어그램 / Architecture Diagram

![표현·로직·데이터 3계층 아키텍처](week-07-architecture.png)

다이어그램 파일: [PNG 이미지](week-07-architecture.png) · [확대·편집용 SVG](week-07-architecture.svg)

표현 계층은 입력과 결과를 보여주고, 로직 계층은 계산·판정과 작업 순서를 정하며, 데이터 계층은 저장소와 외부 도구 연결을 담당한다. 표현 계층은 로직 계층에만 요청한다. 로직 계층이 정의한 포트(필요한 기능의 인터페이스)를 데이터 계층의 어댑터가 구현한다. 이에 따라 로직에서 Blender·SMPL·fal 등의 외부 SDK를 직접 호출하지 않는다.

그림의 작업 요청은 **표현 → 로직 → 포트를 통한 데이터·외부 도구 실행**으로 이어지고, 결과는 역방향으로 전달된다. 포트 구현 관계는 실행 순서와 별개이며, 데이터 계층이 로직의 인터페이스를 따른다는 뜻이다.

### 1-1. 프로젝트 범위와 결과물

| 구분 | 내용 |
|---|---|
| 대상 의류 | AI Hub 의류 데이터 중 반팔 라운드넥 티셔츠 10~20벌. 치수·색·원단 정보 사용 |
| 패턴 견본집 | 정핏·오버핏 등 치수·형태가 다른 반팔 라운드넥 패턴 10개 이상. 패턴 ID·도면·생성 파라미터·측정 치수를 함께 저장 |
| 사용자 입력 | 키, 가슴둘레, 허리둘레, 어깨너비, 팔길이 + 등록된 티셔츠 선택 |
| 최종 결과물 | 부위별 핏 리포트 + LTX 2.3 render-to-real 실사 착장 영상 + 대표 프레임 |
| 보관할 중간 결과 | 패턴 견본집, 의류별 선택 견본 ID·최적화 기록, 티셔츠별 3D 옷, SMPL 몸 메시, 착장된 `.blend`, 정면 렌더 클립, 검증 기록 |
| 실행 환경 | 몸·옷 준비, 핏 계산, Blender 작업은 Mac. 실사화는 fal 클라우드 API 사용 |
| 필수 범위에서 제외 | 상품 사진 수집, 별도 인물 사진 생성, 별도 회전 영상 생성, 예측 모델 학습, 히트맵 |

패턴 견본집을 사전에 생성하고, 의류를 등록할 때 치수가 가장 비슷한 견본을 골라 최적화한 뒤 티셔츠별 3D 옷을 저장한다. 매 피팅 요청에서는 완성된 등록 의류를 불러온다. 신체 입력 후 **핏 판정 경로와 3D 몸 생성 경로를 독립적으로 실행**하여, 핏 리포트가 3D 착장이나 실사화 완료를 기다리지 않게 한다.

### 1-2. 계층별 책임과 의존 관계

| 계층 / Layer | 모듈·기능 / Modules | 의존하지 않는 것 / Does not depend on |
|---|---|---|
| 표현 / Presentation | 신체 치수 입력·티셔츠 선택 화면, 핏 리포트·실사 영상·대표 프레임 표시, 진행·실패 상태 표시, 외부 전송 안내, 견본집 생성·의류 등록용 관리 화면 또는 명령어 도구 | 핏·최적화 계산을 직접 수행하지 않는다. 저장소·외부 SDK를 직접 호출하지 않고 로직 계층에 요청한다. |
| 로직 / Logic | 피팅 서비스·견본집 생성 서비스·의류 준비 서비스, 여유량 계산·핏 판정, 견본 생성 계획·치수 비교·검색 순위 결정·선택 견본 최적화, 몸 최적화, 착장·정면 렌더·실사화 작업 조정, 대표 프레임 추출·색·실루엣 검증, 실패 처리, 저장·생성·검증 포트 | 화면의 구현 방식, 파일·DB 저장 방식, 특정 외부 SDK를 알지 않는다. 외부 기능은 자신이 정의한 포트로 사용한다. |
| 데이터 / Data | 견본 패턴·ID·생성 파라미터·측정 치수 저장소, 신체 입력·의류 치수·색·원단·결과 저장소, AI Hub 데이터 변환, GarmentCode·SMPL·Blender·fal/LTX·미디어 처리·검증 도구 어댑터, 중간 파일·최종 결과 보관 | 화면을 알지 못하고 견본 검색 순위·핏 판정 기준이나 전체 작업 순서를 정하지 않는다. 로직 계층의 포트를 구현한다. |

실루엣 비교 방법은 검증 포트 뒤의 구현으로 선택한다. 분할 모델은 선택지이며, 필수 기술로 확정하지 않는다.

### 1-3. 단계별 처리 흐름

| 단계 | 처리 | 결과 |
|---|---|---|
| 0. 사전 준비 | GarmentCode로 반팔 라운드넥 패턴 견본집 생성 → AI Hub 티셔츠 선별 → 의류 치수표로 가장 비슷한 견본 검색 → 선택 견본의 복사본 최적화 | 견본집 + 등록 의류 정보 + 선택 견본·최적화 기록 + 티셔츠별 3D 옷 파일 |
| 1. 입력 | 신체 치수 검증, 등록 티셔츠 선택 | 사용자 프로필 + 선택 의류 |
| 2. 핏 판정 | 신체·옷 치수 비교 → 부위별 여유량 계산 → 기준표에 따른 판정·문장 생성 | **핏 리포트: 독립적인 최종 결과물** |
| 3. 몸 생성 | SMPL 몸 생성 → 재측정 → 입력과의 차이 최적화 | 몸 메시 + 부위별 오차 기록 |
| 4. 3D 착장 | 몸과 등록된 3D 옷 결합, 원단 물성을 반영한 Blender 천 시뮬레이션 | 착장 `.blend` + 확인용 3D 미리보기 |
| 5. 실사화·검증 | 옷 색 적용 → 정면 고정 카메라 클립 렌더·보관 → fal/LTX 실사화 → 대표 프레임 추출 → 색·실루엣 비교 | **실사 착장 영상 + 대표 프레임 + 검증 기록** |

핏 계산의 기본식은 다음과 같다.

- 가슴 여유(cm) = 옷 가슴단면(cm) × 2 − 몸 가슴둘레(cm)
- 어깨 차이(cm) = 옷 어깨너비(cm) − 몸 어깨너비(cm)

타이트·정핏·여유·오버핏의 경계값은 부위별 기준표로 관리한다. 입력에 없는 신체 위치를 추정해 총장 설명을 만들 때는 추정 방법을 정하고, 결과에도 추정임을 표시한다.

### 1-4. 견본집 생성·검색·최적화

견본은 **치수와 생성 파라미터가 붙어 있는 티셔츠 도면·패턴**이다. 다음 세 작업을 연결해 의류 등록의 시작 패턴을 정한다.

| 작업 | 입력·처리 | 출력 |
|---|---|---|
| 견본집 생성(#4) | GarmentCode의 반팔 라운드넥 패턴에서 몸판 폭·총장·어깨·소매 등을 달리해 정핏·오버핏 등 견본 10개 이상 생성 | 패턴 ID·도면·생성 파라미터·측정 치수가 연결된 견본집 |
| 견본 검색(#5) | 등록할 옷의 치수표와 견본 치수를 공통 기준으로 비교하고, 합의한 비교 방식으로 가장 비슷한 1개 선택 | 선택 견본 ID·치수·비교 결과 |
| 선택 견본 최적화(#6) | 선택 견본을 복사해 대상 옷의 치수표에 맞게 조정하고, 다시 측정해 오차 확인 | 원본 견본을 보존한 의류별 패턴·3D 옷·오차 기록 |

예를 들어 가슴단면·총장·어깨너비가 각각 A=(48, 65, 42), B=(52, 69, 46), C=(58, 74, 52)cm이고 대상 티셔츠가 (53, 70, 46)cm라면, B를 시작 패턴으로 골라 가슴단면과 총장을 조정하는 흐름이다. **이 수치는 설명용 가정값이며, 실제 검색 방식과 판정 기준은 팀에서 정한다.** 견본의 정핏·오버핏 명칭은 패턴 구분이며 사용자별 최종 핏 판정은 #2에서 별도로 계산한다.

**견본 10개 이상은 시작 패턴의 수이고, 등록 의류 10~20벌은 완성할 티셔츠의 수**이다. 견본 생성·검색·최적화는 의류 등록을 위한 사전 준비에서 수행한다. 사용자가 신체 치수를 넣을 때마다 견본을 다시 검색하지 않는다.

| #10 | 정면 렌더 클립 생성·LTX 실사화 | ai | 화면·실사화 | 옷 색을 적용한 정면 고정 카메라 클립을 렌더하고 원본을 보관한다. 문서의 fal/LTX 2.3 render-to-real 경로로 실사 영상을 생성·저장한다. 프롬프트에 의류 색·원단을 반영하고 오디오 생성은 끈다. Light 설정을 우선 확인하며, 사용 가능한 실제 설정·요청·오류를 기록한다. |
| #11 | 대표 프레임 추출·색·실루엣 검증 | ai | 화면·실사화 + 옷·패턴 | 실사 영상에서 대표 프레임을 추출한다. 대응하는 렌더 프레임과 색·실루엣을 비교하고 방법·기준·판정 결과를 저장한다. 합의한 통과·실패 기준 사례를 기대 결과대로 판정한다. 기준 초과 결과는 검증 실패로 표시하여 정상 결과와 구분한다. |
| #12 | 실패해도 핏 결과 제공 | logic | 핏·서비스 + 화면·실사화 | 3D 또는 실사화 단계가 실패해도 유효한 입력의 핏 리포트는 제공한다. 가용한 3D 미리보기와 실패 단계를 표시한다. 대체 결과를 실사화 성공으로 처리하지 않으며, 3D·실사화 실패가 핏 리포트 표시를 막지 않는지 확인한다. |
| #13 | 통합 실행·설치 안내 | infra | 전원 | 다른 팀원 컴퓨터에서 설치·API 설정 안내를 따라 견본집 생성·의류별 견본 검색·최적화의 사전 준비를 재현하고, 합의한 기준 사례로 피팅 1회를 실행한다. 핏 리포트·실사 영상·대표 프레임·검증 기록이 생성되고, 결과가 합의한 색·실루엣 검증 기준을 통과한다. 견본 10개 이상과 등록 의류 10~20벌의 목록·연결 관계 및 중간 결과 저장 위치를 확인하고, `PROMPTS.md`에 AI 사용을 기록한다. 공개 서비스 전 어댑터·도구의 이용 조건을 확인한다. |
